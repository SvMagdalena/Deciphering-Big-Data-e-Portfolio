Unit 10 — Security

API Security Requirements

I used a proposed GitHub REST API → Python → JSON → SQLite workflow to evaluate common security risks. The specification considered restricted access tokens, HTTPS, input validation, rate limits, safe error handling, parameterised SQL queries and avoiding personal or sensitive data unless justified. A fictional offline JSON to SQLite example passed six tests. It illustrates the checks that could be applied to API responses, but it was not a live authenticated API connection.

IBM QRadar–INTELLAS–KAIF

The reading showed how integration pipelines move data between systems. IBM QRadar’s Device Support Modules (DSMs) parse incoming events, while the INTELLAS case study covers a broader integration with KAIF. The key lesson was that secure connectivity also depends on correctly interpreting the received data.

Evidence: API security specification, offline validation results and study of the linked IBM/INTELLAS materials.
